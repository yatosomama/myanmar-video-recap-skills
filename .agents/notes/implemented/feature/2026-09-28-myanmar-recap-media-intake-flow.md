# Agent Note: 缅甸语短剧解说素材接收与自动开工流程

## Problem

`video-recap` 已把默认成片语言设为缅甸语，也支持多个视频按 cut 模式串联；但入口只示范视频路径，字幕只以 `--context` 提示语言和路径，没有规定读取/配对 SRT 的做法。当前流程表把 cut 的两个 Agent 阶段标为暂停点，可能被理解为每阶段都要停下来问用户。用户希望提供前几集和中文字幕后即可开工，同时在缺少必需素材时能一次问清。

## Decision

`skills/video-recap/SKILL.md` 将“多集短剧视频 + 对应中文字幕 SRT”设为默认缅甸语解说入口：素材与配对清楚时使用所有已提供剧集立即开工；缺少视频/字幕或 SRT 与集数映射仍无法推断时，只汇总询问缺失项。默认 Edge TTS、缅甸语；已给出的画幅、时长、集数范围及声线沿用用户要求，未指定的时长不额外追问。

Agent 在创作前实际读取每份 SRT，核对集数、时间范围和配对，并把角色名、关系、关键事件和钩子整理到 `work_dir/source_subtitle_notes.md`；精简剧情摘要和路径进入 `--context`，创作阶段回看逐集字幕笔记。当前 `recap.py` 没有 SRT 原生参数，文档明确不能只传文件路径就假设脚本已导入字幕。cut-first-narrate-second 的两个时间轴/写作阶段继续保留为内部切点；完整输入齐全后，Agent 在同一任务里继续处理，不把阶段切点变成用户审批停顿。

## Alternatives considered

- **新增 CLI SRT 参数并替换 ASR 产物** — 最强理由：脚本能够直接校验并消费字幕，减少 Agent 手工交接。否：这属于更大的跨技能接口变更，涉及 provenance、多个字幕/视频配对和缓存，本次先明确现有能力边界与 Agent 侧读取契约。
- **保留现有模糊入口** — 最强理由：没有新流程文案。否：不能保证模型知道先问哪些文件，也可能只传路径不读字幕，或在内部阶段不必要地停下。
- **取消 cut-first-narrate-second 的阶段边界** — 最强理由：表面上可以压成单阶段流水线。否：旧实现记录了原片时间机械映射会造成旁白失步；本次只消除用户审批式暂停，不移除先剪后写和按剪后时钟编写旁白的步骤。

## Consequences

- **收益**：用户一次提供视频和相配中文字幕后，Agent 能立即处理所有素材，无须重复询问默认语言或中间阶段确认；SRT 实际内容成为剪辑与解说依据。
- **代价**：本次没有给 CLI 增加 SRT 原生参数；长字幕需要按集摘要，真正无法判断的素材映射仍需用户澄清。技能结构验证通过，CLI 帮助可以正常启动；文档改变未加入新的回归测试。
