## Problem

本仓库把中文解说作为默认写作目标，配音器没有无需 API 密钥的缅甸语 TTS 供应商。用户希望短剧输入稳定产出缅甸语解说，并以已配音视频和中文字幕作为剧情及剪辑依据。

## Decision

将 video-recap/video-script 的默认创作契约改为缅甸语解说；新增缅甸语本地化参考，规定中文字幕优先、剧情钩子与人物关系核验、解说节奏及混音留白；新增 Edge TTS provider，默认使用 `my-MM-ThihaNeural`，允许 `my-MM-NilarNeural`。默认旁白语速为 1.27；解说成片不自动恢复已配音原片对白。用户要求去掉原剧配音时，整条原片混合音轨不进入成片。

## Alternatives considered

- 只加一份缅甸语写作说明：不改运行时供应商，仍要求 MiMo/Fish 密钥，无法满足用户要用免费 Edge TTS 的要求。
- 只提供手动生成 MP3 的命令：不能与现有分段、缓存、归一化及 recap 混音流程配合。

## Consequences

默认新稿和默认 TTS 都改为缅甸语，现有显式 MiMo/Fish/Index 配置仍可选择。更快的默认节奏减少了旁白占用时间；用户要求完全去掉原片配音时会同时失去混在同一音轨的音乐和音效，只有做完对白分离时才能保留非人声背景。Edge TTS 通过 Microsoft 在线语音服务工作，需要网络；它不使用本地模型，也没有离线保障。该改动会改变本仓库的默认解说语言。
