## Problem

新 Agent 使用短剧 skill 时会先读到较长的串行创作流程，要求多份中间计划和层叠审阅；这增加上下文、工具往返和用户感知等待。直接自动删静音或降低帧覆盖又会伤害短剧对白、停顿、动作与连接质量。

## Decision

多集短剧默认先批量读取 SRT 与媒体元数据，再用联系表筛出剧情候选，只对候选段和真实接点精查；互相独立的逐集场景/元数据准备并行。Agent 用紧凑编辑板支撑 clip plan 与缅甸语旁白。背景调研、完整机器索引和额外语义评审按需升级。输入配对、画面证据、对白/旁白声音所有权、完整 TTS 段、接点和最终成片检查保持必需；Agent 简短报告进度，不输出冗长思维过程。

实现只复用仓库已有的场景检测与联系表思路，不新增自动删静音依赖：Auto-Editor 将静音/低响度移除作为其常见 first pass；PySceneDetect 的 Content/Adaptive 检测用于找场景切点。二者启发“先廉价粗筛再看候选”的分层流程，但它们的检测分数不决定剧情价值或交付剪点。

## Alternatives considered

- **直接删静音或大幅降低抽帧率** — 最强理由：减少分析与导出时长最直接。否决：短剧停顿、表演反应和完整对白可能因此受损，源端自动判据无法代替剧情剪辑。
- **默认安装 Auto-Editor/PySceneDetect 作为新依赖** — 最强理由：有现成的静音/场景分析与自动剪辑程序，避免重新实现候选检索。否决：当前仓库已有场景检测和 contact-sheet；Auto-Editor 的响度规则面向低风险口播清理，不能直接替代短剧的剧情选段；额外依赖也会增加新 Agent 首次运行的环境准备时间。
- **取消所有 QC / 声音边界规则** — 最强理由：减少流程阶段。否决：用户历史问题集中在原声叠音、抢话和剪点衔接，移除这些门禁会复发质量缺陷。

## Consequences

- **收益**：默认分析聚焦剧情候选，不逐场景堆叠长文本与重复评审；用户更快看到明确进度和首个剪辑方案。
- **代价**：快速筛选依赖字幕质量与场景缩略图；疑难、字幕错位或人物关系复杂的段落需主动切到深度复核，因此耗时会增加。
