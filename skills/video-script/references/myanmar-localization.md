# 缅甸语短剧解说本地化

## 默认目标

本仓库默认把用户提供的剧集、短剧或电影剪成缅甸语剧情解说。旁白、独立旁白字幕、标题和交付说明使用缅甸文（မြန်မာစာ）。只有用户明确指定另一目标语言时才切换。不要把中文字幕逐句直译成解说；先理解人物关系、动机、因果和每集结尾，再为缅甸观众重写。

## 理解素材

1. 用户提供的中文字幕是剧情线索和时间锚点。逐集读完字幕，合并被拆开的句子；遇到错字、漏句、角色名混乱或时间戳异常时，结合画面与原声修正，并在项目记录中写明不确定处。
2. 将字幕时间与对应视频逐集绑定。多集不得把一集的时间戳套到另一集；剪辑记录保留 episode/source ID、源入点、源出点和输出入点。
3. 中文字幕可能是对白、旁白、画内文字或制作字幕，不能一概当成角色台词。角色名字、亲属关系、时间跳跃和因果以多条证据互相核对；字幕和画面冲突时标注冲突，不猜测隐藏剧情。
4. 找每集的状态变化：谁发现了什么、关系如何改变、观众新增了什么问题。优先留下公开羞辱、反转、身份线索、情绪反应和能支撑下一拍的具体画面。

## 故事节奏

将连续剧集重组为清晰的一条主线。可以先用强冲突或疑问开场，再补必要背景；每一段都要推进因果或情绪。结尾停在本轮素材真正兑现的悬念，不替观众解释尚未发生的答案。

改写为解说而非逐字翻译：

- 保留影响理解的事实、动机、关系、转折和悬念；删掉重复问候、无变化的寒暄和重复镜头。
- 每个爆点先铺垫，再让画面或原声兑现，旁白不要提前说穿；冲突后留一小段反应或安静。
- 不编造人物想法、医学结论、身份、时间或后续结果。若字幕只暗示，不把暗示说成已经证实。
- 人名和称呼建立一次性词汇表，后文稳定使用同一缅甸文写法；确需保留中文专名时采用统一音译，不在同一片中混用写法。

## 缅甸语口语

- 用自然、易听的现代缅甸语写给普通观众；按缅甸语语序重组句子，避免中文语序和逐字翻译腔。
- 一句只讲一个动作或因果，长句拆短。段落间使用自然转承，避免连续堆叠“然后”。
- 旁白像讲故事的解说员，语气清楚、有温度、有起伏；羞辱与背叛可压低、克制，反转提高力度，温情段放松，悬念收慢。
- 避免生硬书面语、过度夸张的网络口号、无依据的道德评判和重复复述画面里观众已经看见的动作。
- 正式出稿前朗读或合成试听一遍，检查断句、长词、数字、专名和句末语气。Edge TTS 对缅甸语标点/停顿的表现以实际试听为准。

## 旁白与原声音轨

- `audio_owner` 每拍只选一个主导者：旁白、原剧对白/表演声、动作声或沉默。旁白需要解释关系/因果/时间跳跃；能由表演完成的地方优先留给演员。
- 解说围绕原剧已配音音轨剪辑时，避免旁白压过关键一句对白。优先用完整对白句子前后作为旁白窗口；无法腾出空间时缩短整段解说或删掉次要信息，不能切断半句台词。
- 旁白连续成块，避免每个字幕短句都切一次；不同情绪段之间留呼吸，冲突爆发后的表情和音乐回响不要马上盖住。
- 旁白音量清晰居前。已配音原片进入剧情解说后，不得在旁白空隙自动恢复原剧对白；只保留用户明确指定的原声句或表演点。
- 缅甸语解说覆盖已配音片源时，默认不在解说下方保留低音量中文对白；`FOREIGN_SOURCE_AUDIO` 的默认值 `0.05` 仍可听见原声，不能当作静音。若用户要求只听缅甸语解说，运行 recap/assemble 时显式设 `IDLE_ORIG_VOLUME=0`、`SPEECH_DUCKING_VOLUME=0`、`ZONE_DUCKING_VOLUME=0` 且 `DUCKING_MODE=fixed`，并关闭 BGM；静音原片完整混合音轨，不得只在旁白说话时静音。若用户要求完全去掉原剧配音，原片对白与 BGM/音效混轨时仍须静音整条原片音轨；若要保留 BGM/音效，先分离对白与伴奏并试听确认对白已去除。
- 若片源已有烧录字幕，禁止再把旁白字幕烧在同一区域。仍可生成独立的缅甸语旁白 `.srt` 供用户选择；交付中说明它和片内已有字幕的关系。

## 字幕与混音本地化覆盖

- 用户要求遮盖原片硬字幕并烧录缅甸语解说字幕时，先测量硬字幕带并用高斯模糊遮盖；字幕配置采用 `SUBTITLE_ALIGNMENT=5` 使解说字幕居中落在模糊带内，`SUBTITLE_FONT_SIZE=72`、`SUBTITLE_MAX_CHARS=14` 作为 1080×1920 竖屏起点。字号仍由字幕带实际高度约束，必须抽帧确认没有裁字或压脸。
- 用户要求保留原片气氛时，只在旁白窗口下保留已分离并试听确认的人声分离伴奏，其他时间恢复完整原片声音；旁白用 `NARRATION_GAIN_DB=4` 作为初始响度提升值，检查综合响度、真峰值与人声清晰度后再微调，不提升原片间隙音量。
- 源声音恢复点必须根据变速/音高处理后实际播放的 TTS WAV 起点与文件时长计算，并在尾音后留短释放余量；不可把字幕 cue 的结束时间或旁白段落的规划结束时间当作实际讲话结束。若时间变换后字幕需同步，应一并按同一实际语音时钟更新。

- 默认 provider：Edge TTS，voice `my-MM-ThihaNeural`。女声可由用户明确选用 `my-MM-NilarNeural`。
- 默认整体语速使用 `NARRATION_SPEED=1.27`，保持清楚的句间停顿；用户反馈仍偏慢时分段小幅提速，并复听专名、数字和尾音，累计提速不超过 `1.40`。若 Edge TTS 已使用较快的原生语速（例如 `rate=+25%`），渲染时显式设 `NARRATION_SPEED=1.0`；只有完整音频确实超出下一段可用起点时才让逐段适配加速，不能再叠加全局 `atempo`。优先缩短旁白或延长旁白窗口，不裁尾。
- 除非用户明确要求角色配音，解说保持单一 narrator 音色；不要把 Edge TTS 用成逐角色对白重配。
- Edge TTS 是联网服务。离线、限流或请求失败时保留解说稿和已有工作文件，报告失败段，不把中文稿或静音冒充成缅甸语交付。
- 每次先用一小段验证语音服务、发音和输出电平，再批量生成；生成后检查每段时长、尾音和文件完整性。不得把合成音频硬裁短以塞进时间窗。
