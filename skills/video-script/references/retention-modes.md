# 按素材选择短剧剪辑模式

目标是让第一次看的观众愿意继续看、听懂并得到回报。没有发布数据时，不给“爆款概率”或伪精确评分。下面的时间仅是首稿检查窗，完整台词、动作与表演优先；不为了缩短几秒剪成半句。

## 1. 先定一条主线，再选模式

一次读取本轮全部中文字幕，找出有时间证据的“人物选择 → 代价/阻力 → 变化”。模式由当前素材决定，用户指定的顺序、完整版本或修改范围优先。默认选择一条主线，避免五集轮流摘要、多人物同时开坑。

| 模式 | 适用素材 | 开头与推进 | 本片结束 | 主要风险 |
|---|---|---|---|---|
| 冲突 `conflict` | 拒绝、威胁、背叛、反击，有清晰双方与赌注 | 最短且自明的冲突对白/动作 → 补必要关系 → 对抗升级 | 本次选择/反击及对方反应 | 只截骂人台词，观众不知道谁为什么生气 |
| 揭示 `reveal` | 身份、误会、证据逐步改变判断 | 可观察的异常/矛盾 → 线索与代价 → 真实揭示 | 答案及其影响；尚无答案时完成一个局部问题 | 在开头直接报最终身份，后文失去观看理由 |
| 情感 `emotion` | 牺牲、离别、关系抉择，反应与停顿有价值 | 有代价的选择/关系裂缝 → 最少背景 → 抉择和回应 | 反应、沉默或关系变化 | 按固定节奏切掉情绪落点、用高声旁白覆盖表演 |
| 顺叙 `story` | 信息密集、依赖前因、前几集尚未形成完整反转 | 最早有价值的变化 → 清楚因果 → 阻力与新选择 | 已发生变化 + 有证据的下一步问题 | 为了“炸裂”强行倒叙或捏造后续结果 |

若某个爆点离开前情就无法理解，先保留一句必要前提，或换一个自明开头。素材缺少强对白就以画面加旁白开场；原声高光不设数量和时长比例配额。没有可证实的反转就选顺叙。

## 2. 开头只比较少量真实候选

最多比较三个候选，仅在现有编辑板记录：来源集/秒、画面或对白证据、观众马上能理解的赌注、后文兑现位置、选用/淘汰的具体理由。不对全部句子打关键词分，不扩展成额外报告。

- 第一个约 3–5 秒窗口检查：观众能感知一个具体冲突、异常或选择吗？删片头、寒暄、泛泛的“故事开始了”，保留理解和表演所需内容。
- 开头的内容必须出现在当前素材；不写“全网震惊”“最后你绝对想不到”替代事件。缅甸语先表达人物动作与代价，避免中文逐字翻译和堆砌修饰。
- 若提前展示后面的片段，观众必须能辨认这是预览/时间跳转；不能拼成当下发生的虚假因果，也不能删除真正理解结果所需的前提。原声段从可靠句界开始。
- 默认只渲染选中的一个开头。后续用户要求对比或提供留存数据时，只替换开头/对应连接段，复用未改动的素材与 TTS。

## 3. 中段兑现，声音接力

每一拍写清“新增了什么、为什么接上一拍”，删除重复复述；关键反应、动作结果和完整对白具有剧情价值时保留。人物、地点或时间改变时，在对应画面用最短必要缅甸语连接说明，不让旁白说下一件事而画面还在上一件事。

给每拍一个主导声音：旁白补压缩掉的因果，原片高光承担真实对白和表演。旁白窗口内原片人声完全静音，原声对白窗口内没有旁白；按最终 TTS 实测结束点和淡入保护区安排接力，不按估计字数提前恢复原声。声音太长先缩写整句或扩展相关真实画面，再在已有安全范围调速；不无限加速、不裁尾、不用无关画面补时长。

解说字幕使用 TTS 词级时间随声音结束，模糊只覆盖实测原字幕带且仅在旁白窗口启用；对白窗口保留原片字幕。文字大到可读并落在模糊带中央，实际画幅放不下时分成短 cue，不能缩到看不清。

## 4. 把承诺落到已有剪辑契约

首次 CREATE 的多集短剧快速路径，默认将选中的开头事件与本片兑现/情绪落点记入同一 `clip_plan.json.required_evidence.nodes`，并声明可选位置约束。不新增编辑板 JSON。REVISION 保留原有冻结要求，旧数组计划仍兼容。

```json
{
  "nodes": [
    {"id": "hook", "source": "/media/ep1.mp4", "source_id": "ep1", "start": 12, "end": 16, "track": "audio", "content": "完整的拒绝对白，冲突开始"},
    {"id": "payoff", "source": "/media/ep2.mp4", "source_id": "ep2", "start": 30, "end": 35, "track": "video", "content": "针对拒绝作出的决定与反应"}
  ],
  "before": [["hook", "payoff"]],
  "opening": {"node_id": "hook", "max_lead_seconds": 1},
  "closing": {"node_id": "payoff", "max_tail_seconds": 1.5}
}
```

这段是 `required_evidence` 对象，嵌入现有计划；实际节点路径、区间和余量由素材决定。`opening` 限制成片开始到完整开头节点开始的距离，`closing` 限制完整结尾节点结束到成片结束的距离。余量包括真实建立镜头、呼吸和反应；不要机械照抄例子的秒数。原声节点仍需在剪后输出时间的原声对白计划中登记，选段完整不等于最终可听见。

剪点吸附后查看 `clip_plan_validated.json.qc.required_evidence.placements`：开头与结尾均应 PASS，`actual_gap_seconds` 是实际余量。BLOCK 时修剪点或必要的表演区间；不能删约束或放宽到整片长度只为通过。该检查验证完整源片段及位置；内容是否吸引人仍由实际素材和审片判断。

## 5. 一次交付检查与数据回流

正常速度复看开头、中段转折与结尾，再按既有流程完整检查声音、字幕和真实接点。开头的问题须在本片获得明确回报；要追下一集时，先兑现本片问题再打开真实的新问题，不突然截在半句话、不默认添加长 CTA。完整版本优先讲清本轮素材的主线，不能擅自只输出一个短样片。

用户提供发布后的留存曲线、完播/观看时长、评论或点击数据时，才比较同平台与相近时长的成片：开头离开多查理解门槛，中段离开查重复/因果与声画不符，结尾离开查长尾或提前泄底。每次只改最有证据的一项并保留原版本作比较；没有数据时只报告内容与技术检查结果。
